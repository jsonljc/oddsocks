# ODD SOCKS — baseline simulation findings

**Date:** 2026-07-26 (revised 2026-07-27 after the whole-branch review)
**Instrument:** `npm run sweep` (`src/cli/sweep.ts`), heuristic bots on both sides, Hollow House
**Sample:** 12 configurations × 2,000 games = 24,000 games, seed base 0 (deterministic, reproducible)
**Wall-clock:** ~5.4s for the full matrix

This reads the sweep table at the bottom. Read the six limits in the last section before acting on
anything above them — they change what several of these numbers are allowed to mean.

---

## Read this first: two engine defects were fixed after the first draft, and one of them moved the headline

The whole-branch review found two Critical faults. Both are fixed; every number in this document was
regenerated afterwards. The first one changes conclusions, so it is stated before anything rests on it.

**1. The solver was reading Hushed children's true positions.** Bell's constraint computed how many
people stood beside Bell from `midnightPositions` — ground truth — and demanded exact equality with
the announced count. Clem's read ground truth for Clem's own room. And a Hushed child's oddity kept
announcing after the Hush had taken away their claim and their testimony. Under the default
`hushMode: 'silent'`, four or five of six players are Hushed by night five: the children cannot know
where a Hushed child slept, so an oddity built on that knowledge refutes rooms the real table could
never rule out. The solver now works from `knownRoomOf` — a child's own claim, a lit witness naming
them, a spent Bell, or a Keyhole, and `null` otherwise — and Bell's count became an **interval
containment** test rather than exact arithmetic (spec §6.1, R18).

This is the loosening direction, so it cannot manufacture safety for the villain that the rules do
not give: re-verified across all 24,000 games and 167,914 nights, `forcedNight` is still `null`
everywhere and the villain's true room is never dropped from the viable set.

What it did to the numbers is large:

| | before the fix | after |
|---|---|---|
| baseline `lateColl` | 50.5% | **18.2%** |
| the oddities layer's effect on `lateColl` | 17.6% → 50.5% (nearly triple) | 17.6% → 17.8% (**nothing**) |
| the Hush across `silent`/`oneNight`/`none` | 50.5 / 52.0 / 52.1 ("modest") | **18.2 / 31.0 / 52.1** |
| baseline `hiding` | 5.352 | **6.084** (6.067 from C1, +0.017 from the Pike guard below) |

The previous draft's two loudest claims — *"oddities nearly triple meaningful exposure"* and *"the
Hush is a modest, not a large effect"* — were both artifacts of the solver knowing things the table
did not. They are reversed below.

*Decomposition, for anyone reconciling against the review's own measurements:* the review measured
only the solver half of this fix and reported baseline `lateColl` 0.192 and `hush-oneNight` 0.317.
Silencing a Hushed child's oddity as well (R18 — the Hush removes both halves of a child's voice, so
it must remove the half they speak through an oddity too) accounts for the remaining move to 0.182
and 0.310. `hush-none` is 0.521 either way, exactly as it should be: with the Hush off, nobody is
ever silenced and the second half of the fix has nothing to do.

**2. The villain publicly reported its true room every morning.** `runMorning` built a `reported`
event for every player straight from their sighting. R15's honesty rule is scoped to *innocents*; the
engine applied it to everyone. Measured over the 2,000 baseline games before the fix: on **6,743 of
6,743 theft nights** the thief publicly reported the room it had just robbed; on **81.4%** of spoken
mornings (11,339 of 13,934) the report contradicted that same morning's claim; and **7,031** dark-room
reports carried names, which only the villain and Wren can produce.

That falsifies spec §3.4 — *"the villain's only exposure on a theft night is the trail"* — which is
the stated reason trail accuracy is this harness's primary metric. It was inert in practice (no bot
reads `reported.room`, and the solver already excluded the villain's own report), and the corrected
sweep table is identical to the pre-fix one in every game-outcome column, confirming that. It would
not have stayed inert: this document's own top recommendation is to re-run against a stronger villain,
and the first suspicion heuristic to read `reported.room` would have been a perfect villain detector.

The villain's report now carries the room they **claimed**, with no names and no count (R19).
Removing them from the morning entirely was the other option and is strictly worse — on night one
nobody is Hushed, so the single child with no report would be the villain outright.

## The headline: there is really one win condition, and the dodge isn't what's costing the race

`caught` is 0 in every one of the 24,000 games. That is not a bug — it is §7's dodge working exactly
as written. A Call is public; the villain sees its own name on it and walks somewhere else. Rules §1
advertises two children's win routes, catch or survive; against a villain that never fails to notice,
there is effectively one. The question worth asking is not "how often do Calls catch" — it's
**whether forcing that dodge costs the villain enough tempo to lose the race anyway.**

The direct test the brief specifies is `villain` in `baseline` (2-hand Calls) versus `call-hands-3`
(3-hand Calls, much harder to assemble) — every number below is a column in the shipped table:

| | `villain` | `live` | `dodges` | `thefts` (of 5 needed) | `quota` (reached all 5) |
|---|---|---|---|---|---|
| `baseline` | 9.4% | 0.733 | 0.569 | 3.372 | 9.4% (188/2,000) |
| `call-hands-3` | 8.9% | 0.223 | 0.193 | 3.344 | 8.9% (179/2,000) |

Raising the hand requirement to 3 cuts live Calls by ~70% and the dodge rate by ~66% — the villain is
being made to swerve about a third as often — and villain win rate does not move (0.5 points, inside
the ~0.9-point standard error on that difference at N=2,000 per cell). **This sweep finds no
measurable cost from dodging.**

But read that alongside `thefts`: the villain is landing barely two-thirds of the five thefts it
needs, in *both* configurations, and reaches all five in under 1 game in 10 either way. The shortfall
is nearly identical whether Calls are common or rare. That is the honest reading: **something other
than Call-dodging is already capping the villain's success rate**, so this comparison cannot show a
dodge-cost even if the design intends one.

The likely culprit is bot quality, not the rules: `heuristicBot.dusk` is the same function for all
six seats, driven purely by "do I want an item" — it has no theft-target logic at all.
Villain-specific reasoning only exists in `midnight`, one phase too late to correct a dusk position
that wasn't chosen with a target bedroom in mind. When nothing is wanted, `dusk` scores every legal
path equally and picks uniformly at random. A villain that can't reliably be in position to strike is
a villain whose win rate is capped by its own approach, before the Call mechanic gets a chance to
matter. **This sweep cannot distinguish "dodging doesn't cost the villain" from "the villain never
gets far enough for a dodge to be the thing that stops it."** Don't read the flat 9.4% → 8.9% as a
design verdict on the Call; read it as inconclusive, and re-run this specific comparison against a
villain with real approach planning before trusting either direction.

(`quota` and `villain` read identically in both rows here — expected, since neither config lets the
villain self-snuff, the one way a game racks up theft-type events without them all counting toward
the win condition; the two columns diverge for exactly that reason under `hush-silent-freeSnuff`,
see Q6.)

## "Odd Socks can always find a safe lie" is not something this sweep measured

An earlier draft reported `neverForcedRate = 1.000` in all 12 cells as the answer to "can Odd Socks
always find a safe lie" and treated it as the sweep's cleanest empirical result. That was wrong, and
it was a flaw in how the instrument was built, not a bot-quality caveat.

`forcedNight` can never be non-null, for any config, any bot, any seed — not because the villain
plays well, but because `solve` is built so that the villain's *true* claim history is always
internally consistent with itself. `src/analysis/safeLies.test.ts` states this as the solver's own
correctness check, not as an interesting property of the game: *"The true claim history is always
consistent, so no game can be 'forced' unless a constraint is wrong."* So `neverForcedRate = 1.000`
and `medianForcedNight = —` in every cell were never in doubt before a single game was run. Twelve
configurations could not have disagreed. It is kept in the table only because it is the invariant the
solver's own correctness rests on, and it is worth being able to see at a glance that it held.

**The real question is narrower: not whether a safe lie exists, but whether the *only* surviving one
is the incriminating truth, on a night where that actually costs the villain something.** On a theft
night the villain is standing in the robbed bedroom; a claim history narrowed to exactly that one
room is a confession in every way that matters, even though `solve` still calls it "not forced."
Three columns measure this — `collapse` (share of games where the viable set ever narrows to exactly
one room), `medColl` (the median night it first happens), and `lateColl` (share of games where that
narrowing happens on night 2 or later) — all read off the `hidingSpace` array the table already
carried.

**`lateColl` is the number to lead with, and it is 18.2% at baseline.** About one game in five sees
the villain's cover narrow to a literal confession on a night when a theft, a marking, or a Call was
live. That is a real finding, and a far more modest one than this document previously reported
(50.5%, an artifact of the solver reading Hushed children's positions — see the correction at the
top).

**`collapse` alone badly overstates it, and the distribution shows exactly why.** `collapse` runs
85–98% across the matrix (baseline: 85.5%) — but `medColl` is **1** in every single cell, and pulling
the full first-collapse distribution for baseline (N=2,000, same seeds as the shipped table) is
stark: **1,702 of 2,000 games (85.1%) have their first collapse on night 1 itself**, before a single
light has been stolen. Across all six later nights, first collapses number **0, 0, 2, 1, 3 and 1** —
seven games in two thousand. The remaining 291 games (14.6%) never collapse at all.

`lateColl` is nonetheless 18.2% (365 games), not 0.35%, because it asks a different question: *does a
collapse happen at any point after night 1*, not *was the first one late*. In 358 of those 365 games
the villain was also pinned on night 1 and then pinned again later. That distinction matters when
reading the column: a late collapse is almost always a **re-**collapse.

Night 1 dominates `collapse` because it is, mechanically, the single most exposed night in the game —
through the **midnight** phase specifically, not "either phase." Only midnight sightings ever become
public testimony: `runMorning` builds every `reported` event from `midnight.sightings`; its dusk-phase
parameter is literally named `_dusk` and never read. `isLit` returns `true` unconditionally for every
non-bedroom room, and on night 1 every *bedroom* is lit too (nobody has been robbed yet), so any two
of the six players who end **midnight** together, anywhere in the house, walk away having named each
other — one positioning decision, not two, and a far bigger exposure surface than any later night,
where enough bedrooms have gone dark that camouflage exists and the trail's narrower, one-witness
mechanic takes over instead.

**A collapse — early or late — is a close call passed, not a trap that stays shut.** `hidingSpace` is
not monotonic; a pin to one room doesn't stay a pin, and each later night reopens the viable set to
whatever a fresh 4-hop walk and that night's own (often much weaker) constraints allow. That is why
`hiding` (mean rooms viable, averaged over the whole game) sits at **6.084** for baseline — half the
house — even though 85.5% of games hit *some* collapse. `lateColl` answers "how often is the villain's
story pinned on a night that matters"; `hiding` answers "how much average cover they're playing with
across the whole game."

## The Hush is the biggest rule-level lever in the matrix

Spec §3.1 calls the Hush *the one question that could change the design*. With the solver corrected,
the harness finally answers it, and the answer is not subtle:

| | `lateColl` | `collapse` | `hiding` |
|---|---|---|---|
| `hush-silent` (baseline, §4 as written) | **18.2%** | 85.5% | 6.084 |
| `hush-oneNight` (§4's own fallback) | **31.0%** | 88.1% | 4.573 |
| `hush-none` (control) | **52.1%** | 92.2% | 4.416 |

Switching the Hush from "silent forever" to "not at all" **triples** meaningful exposure, 18.2% →
52.1%, a 33.9-point swing — about 24 standard errors on the difference at this sample size. Only
trail radius moves `lateColl` further (89.3% → 3.5% from radius 0 to radius 2), and that is a tuning
dial with a known monotone curve rather than a live design question. Setting those two aside, nothing
else comes close: the next largest move in the matrix is `items-on-map-4`'s 2.5 points
(`lateColl` 18.2% → 20.7%), and items, oddities, marking and Call hand cost are all under a point.

The shape of the curve is the interesting part, and the two columns disagree in a useful way.

On **average cover** (`hiding`), the fallback is nearly as good for the children as switching the
Hush off entirely: `oneNight` at 4.573 sits right next to `none`'s 4.416, and both are 1.5 rooms
below `silent`'s 6.084. Almost all of the average cover the villain gets from the Hush comes from
the **permanence** of the silencing, not from its onset — losing a witness for one night barely
matters; losing them for the rest of the game is what opens the house up.

On **meaningful late pinning** (`lateColl`), the fallback recovers less: 31.0% against `silent`'s
18.2% and `none`'s 52.1% — 12.8 of the 33.9 available points, or about 38%. The remaining 21 points
belong to testimony that only exists if the Hush never silences anybody at all.

So `hushMode: 'oneNight'` — §4's own fallback, which this design had been treating as second-best —
takes essentially all of the average-cover benefit and a bit over a third of the late-pinning
benefit, while keeping the mechanic. If the goal is an evidence engine that still bites in the
endgame, which is exactly what §3.1 worries the Hush destroys, the sweep now says the fallback is the
better rule and roughly how much better.

**One caveat, and it is a real one:** none of this reaches the win rates. `villain` reads 9.4% in all
three Hush cells, to three decimal places. The Hush moves the *evidence economy* enormously and the
*outcomes* not at all — because these bots barely act on evidence (`suspicionFrom` reads only trail
namings, `eyesOpen` and cleared Calls). Read the Hush result as a finding about how much the children
could learn, not about who wins; the second half of that question needs children's bots that use the
claim record.

## The six open questions

### 1. Can Odd Socks always find a safe lie?

Trivially, yes — but that answer is guaranteed by how the solver is built, not measured by this
sweep. `neverForcedRate = 1.000` / `medianForcedNight = —` in all 12 cells is a restatement of
`solve`'s truth-preservation invariant, not evidence about this design. It would read exactly the
same in any config, on any map, with any bots.

The question worth asking instead — does the villain's cover ever narrow to nothing but the truth, on
a night where that costs them something — has a real, config-sensitive answer: **`lateColl` = 18.2%**
at baseline. About one game in five. The raw `collapse` figure (85–98% across the matrix, 85.5% at
baseline) looks far more dramatic but is almost entirely free exposure — 1,702 of baseline's 1,709
collapsing games are first pinned on night 1, before any theft, marking, or Call exists. It doesn't
stick either way: mean hiding space sits at **6.084** rooms, half the house.

### 2. Does the trail identify anyone?

Yes, well above chance, and it is now genuinely the villain's only exposure on a theft night (R19 —
before this pass, the villain also published the robbed room in its own morning report). Baseline
trail accuracy is **53.3%**, against 16.7% (1-in-6) for guessing — about 3.2× better than random.

The radius sweep shows the curve is flat, then falls off a cliff: **54.0%** at `trail-radius-0` (name
only someone who ended midnight in the robbed room itself) is statistically indistinguishable from
baseline's 53.3% at radius 1 — adding the robbed room's immediate neighbours to the pool costs almost
nothing — but accuracy drops sharply to **40.9%** at `trail-radius-2`. The default radius of 1 is
sitting on the flat part of that curve; radius 2 clearly is not.

`lateColl` makes the same comparison far more dramatic than trail accuracy alone suggests: **89.3%**
at radius 0, **18.2%** at baseline, **3.5%** at radius 2 — an 85.8-point swing end to end, versus
`collapse`'s comparatively muted 97.8% → 85.5% → 85.4% (night 1's free exposure floors all three
close together regardless of radius). A ~13-point swing in trail accuracy corresponds to an ~86-point
swing in how often the villain is genuinely, consequentially pinned. The trail's precision compounds
night over night in exactly the place `collapse` alone cannot show it. This is the largest effect in
the matrix and it belongs to the design's own primary evidence engine.

### 3. Can a Call ever assemble two hands? — **yes, and nothing in the rules is stopping it**

Yes, and the previous draft got the reason for the fizzles backwards. It measured `holders` as
*pickups per night* — a flow — and concluded a pool of 0.679 people was too thin to fill a 2-hand
Call. The real stock is now measured directly (`pool`): **2.997 Call-eligible players per night at
baseline** — holding an item and unmarked — against `callHandsRequired: 2`. On nights where a Call
actually resolved the pool averages **3.359**, and **88.6%** of all nights have at least two eligible
hands somewhere in the house. **The item economy is not the constraint.** That much is settled.

So why do **81.1%** of Calls fizzle (6,287 of 7,752 resolved Calls across baseline's 2,000 games)?
The tempting answer is the map, and it is wrong too — or at least far weaker than it looks. Here is
the full decomposition, per resolved Call:

| | mean per Call | |
|---|---|---|
| eligible (holding an item, unmarked) | **3.359** | the pool |
| …**and geometrically able to arrive** | **2.374** | still above the 2 required |
| …and still in reach after a Call-blind dusk walk | 1.311 | not a rules fact — see below |
| …who actually joined | 0.865 | |

The second row is the one that matters, and getting it right takes care about *when* a joiner starts
walking. A Call is posted in the **morning**; the children hear it standing where they ended the
previous midnight, and then have the whole of the next night to arrive — dusk's two edges plus
midnight's two, the four edges `reachableInFourHops` exists to model. Measured from that position,
**2.374** eligible hands can reach the named bedroom, and only **1,394 of 6,287 fizzles (22.2%)** were
geometrically forced. Requiring them to have been armed at posting as well (in the previous night's
`callPool`, reachable, and still eligible when the Call resolves) tightens it to 2.071 and 32.4% —
still a minority.

An earlier version of this section measured reachability from each joiner's *dusk* position on the
resolving night, in a single two-edge walk, and reported 1.311 hands and 77.9% forced fizzles. That
is not geometric possibility: it silently charges the map for a dusk walk `heuristicBot.dusk` had
already spent chasing items, with no reference to the Call at all. The conclusion it produced —
"the Call's cost is distance, not hands" — was unsupported and has been withdrawn.

**The honest reading: at two hands, neither the item economy nor the map is binding — the children's
bot is.** Geometry costs about one hand (3.359 → 2.374) and still leaves the pool above the
requirement. Roughly 70% of fizzles had a legal path that nobody walked. The hand count that actually
shows up is 0 in 2,758 Calls, 1 in 3,529, 2 in 1,239, 3 in 206 and 4 in 20 — a distribution set by
willingness and positioning, not by what the rules permit.

That makes **Call-aware dusk positioning the single cheapest experiment left in this harness**, and it
has to run before any rules change is considered: `items-on-map-2` and `items-on-map-4` barely move
`live` (0.674 / 0.731 against baseline's 0.733) because the pool was never binding, and this sweep
gives no evidence that the map is binding either.

### 4. Does dodging cost the villain the game?

Not measurably — see the headline above. `villain`: 9.4% (`baseline`) vs. 8.9% (`call-hands-3`), a
gap smaller than sampling noise, despite live Calls dropping ~70% and dodges dropping from 0.569 to
0.193 per game. Treat this as inconclusive rather than a clean "no" — the villain's win rate looks
capped by something upstream of the Call mechanic (see the bot-quality note above), so this A/B
cannot yet isolate the dodge's true cost.

### 5. Does marking dominate?

No — and now there is a number for how little it does. Marking fires **0.392 times per game** at
baseline: about once every 2.6 games. (The metric behind the previous draft computed 2.595 per game —
never printed, but Q5's cut recommendation was argued around it. It derived markings as
`activeNights − thefts`, on the stated grounds that there was "no third option," and so counted every
night the villain did nothing at all as a marking. There is a third option and it is the common one:
the villain ends midnight with no lit bedroom to rob and no company in the dark.)

`baseline` (marking on) vs. `marking-off`: villain win rate 9.4% vs. 9.6%, survived 90.6% vs. 90.4%,
hiding space 6.084 vs. 6.094, `lateColl` 18.2% vs. 17.8%, trail accuracy 0.533 vs. 0.533 — all flat,
all inside noise. The only effect marking has anywhere in this matrix is a small drag on the live-Call
rate (0.733 vs. 0.761, ~4% relative) and on the eligible pool (2.997 vs. 3.039), consistent with
marked item-holders being unable to join a Call, exactly as designed.

**Marking remains the cleanest complexity-cut candidate this sweep found**, and the frequency number
is what makes the case: a rule that fires once every 2.6 games and moves no metric except
a 4% relative dip in a Call rate that is already dominated by geometry is paying rent in explanation
cost it does not earn back.

### 6. What are the side win rates, and by which route?

Across every cell: `caught` is 0%, `survived` is ~87–93%, and `villain` (lightsOut) is the remainder,
~7–13%. Concretely at baseline: villain 9.4%, caught 0%, survived 90.6%. The overwhelming majority of
children's wins are "the villain ran out of nights," not "the villain was trapped."

The free-snuff Hush exploit is the one cell that shifts this meaningfully: `hush-silent-freeSnuff`
(self-snuffing buys an extra night on the clock instead of costing one) pushes villain win rate to
**12.9%**, up 3.5 points from baseline — a real, sizeable move at this sample size, and the clearest
confirmation in the matrix that the free-tempo exploit §3.1 flagged does what the concern said it
would. The villain takes that deal in **0.358** games out of one (35.8% of games — it can happen at
most once, since a villain owns one bedroom), and it visibly buys them room: `thefts` rises to 3.862
and markings to 0.507.

It's also the one cell where `quota` (20.7%) and `villain` (12.9%) visibly pull apart — everywhere
else they read identically. The self-snuff counts as one of the `thefts` a game needs to reach its
quota, but does not darken one of the five bedrooms the win condition counts (the villain's own
bedroom is deliberately excluded from `darkBedroomCount`, so cover doesn't double as progress).
`quota` rises 11.3 points over baseline (9.4% → 20.7%) while `villain` rises only 3.5 (9.4% → 12.9%):
most of the apparent quota gain doesn't cash out as a win, consistent with a good share of those
extra theft-type events being the self-snuff itself rather than a fifth productive theft.

## Which layers earned their place

Comparing the three build rungs — `core-only` → `core+items` → `baseline` (+oddities, +marking):

| | villain | survived | thefts | collapse | lateColl | hiding | trailAcc | posted | live | pool |
|---|---|---|---|---|---|---|---|---|---|---|
| `core-only` | 7.2% | 92.8% | 3.280 | 85.1% | 16.7% | 6.432 | 50.3% | 3.047 | 0.414 | 1.320 |
| `core+items` | 9.3% | 90.7% | 3.374 | 85.2% | 17.6% | 6.399 | 53.6% | 4.666 | 0.784 | 3.074 |
| `baseline` | 9.4% | 90.6% | 3.372 | 85.5% | 18.2% | 6.084 | 53.3% | 4.663 | 0.733 | 2.997 |

**Items clearly earn their place.** Adding them nearly doubles the live-Call rate (0.414 → 0.784),
pushes posted Calls up 53% (3.05 → 4.67), and more than doubles the eligible pool (1.320 → 3.074) —
the heuristic children only propose a Call when they personally hold an item to back it
(`suspectCall`/`selfNominate` both gate on `held.length > 0`), so without items the accusation
mechanic is close to inert, not merely under-armed. Items also move villain tempo a real amount
(`thefts` 3.280 → 3.374, `villain` 7.2% → 9.3%) and trail accuracy by 3.3 points.

**Oddities do far less than the previous draft claimed.** That draft reported `lateColl` nearly
tripling (17.6% → 50.5%) when oddities were switched on. With the solver no longer reading Hushed
children's true positions, the honest comparison (`core+items` → `marking-off`, which differ only in
the oddities flag) is **17.6% → 17.8%** — nothing, well inside noise. What oddities do move is
average cover: `hiding` drops from 6.399 to 6.094, about 5%, and trail accuracy and Call rates barely
budge. So the layer constrains the villain's story a little, on average, and essentially never enough
to pin it.

Two caveats on that comparison. The `layers.oddities` flag is not a clean A/B of the three public
oddity constraints: it also switches on Wren's dark-sight and Moss's double carry capacity. And two
of the ten constraint rows in spec §6.1 — Keyhole and the spent Bell — contributed **nothing** to
any number in this matrix, because no item was ever spent (Limit 6). Whatever oddities are worth,
this sweep has measured only part of it.

**Marking is the weakest layer measured here.** Isolated (`marking-off` → `baseline`), it fires 0.392
times per game and its only visible effect is the ~4%-relative live-Call dip noted under Q5.
`thefts`, `collapse`, `lateColl`, `villain`, `survived`, `hiding` and `trailAcc` are all flat across
that comparison. Three configurations bracket it (`core-only` has it off structurally, `marking-off`
isolates it explicitly, `baseline` turns it on) and none show it doing more than trim an already
geometry-limited Call pool a little further.

One footnote on the `core-only` row: `pool` reads **1.320** there even though `layers.items = false`
disables both map-spawning and pickup. The Grip (`theft.ts`) hands a robbed player an item straight
from the reserve when the villain wasn't already carrying one, and that path is **not** gated by the
items layer — it's core-rung behaviour per the build order in §8. So a real trickle of item-holders
exists with the items layer off, which is why `live` is 0.414 there rather than 0. (The previous
draft's `holders` column read exactly 0 here and needed a paragraph to explain why; the stock measure
just shows the Grip's contribution directly.)

## What this harness cannot see

Six limits that change what the numbers above are allowed to mean. These are not hedges to skim — a
reader who acts on this document without them will draw conclusions the data doesn't support.

1. **`encntr` (encounter rate) is the least trustworthy column in the table and should not be argued
   from.** It sits at 0.061–0.074 everywhere, barely moving across 12 very different configurations —
   which is itself the tell. Heuristic bots do not cluster, follow, or camp a room the way six people
   around a real house would; this number reflects bot movement habits far more than it reflects the
   design. Reported because the brief asks for it, not because it settles anything.

2. **Every result above is an upper bound on available signal, not an estimate of it.** R15: every
   innocent who can report, does — truthfully, immediately, with no utterance budget. The real game
   gives each player four utterances a morning and the choice of what to spend them on. A real table
   will produce less signal than this harness ever can, not more. Read every number here as "at
   best," never as "expect this."

3. **The morning is entirely unmodelled.** No board, no six-symbol language, no arguing about whose
   claim to trust, no persuasion. The harness validates the night's information economy — whether a
   safe lie exists, whether a Call can physically assemble — and is silent on whether the social game
   built on top of that information actually plays well. A clean baseline here is not evidence the
   full game works; it's evidence the plumbing underneath it does.

4. **Bot-independence and meaningfulness are two different properties.** `forcedNight`,
   `hidingSpace`, `collapseRate`, `medianCollapseNight` and `lateCollapseRate` all come from `solve`,
   which computes from the record and never reads what the villain bot actually claimed — so none of
   the five are contaminated by the villain's lying quality. (For scale: **39.3%** of the villain
   bot's lies land outside the solver's own safe set — 4,457 of 11,339 lying mornings at baseline,
   which is 32.0% of all 13,934 spoken mornings. Before the solver correction those figures were
   46.8% and 38.1%; a looser, more honest solver forgives more of the bot's bad lies, which is the
   expected direction. An earlier draft of this limit said "roughly half," which was right about the
   old solver and is now wrong.) But bot-independence only guarantees a number is *reproducible*, not
   that it's *informative*. `forcedNight`/`neverForcedRate` are bot-independent **and structurally
   constant**. The other four are bot-independent **and genuinely config-sensitive**. Trust all five
   not to be artifacts of bad villain lying; trust only the latter four to tell you anything, and
   `lateColl` specifically over `collapse` when the two disagree. Every win-rate number in this
   document (`villain`, `caught`, `survived`, `thefts`, `quota`, `dodges`, and by extension the whole
   "does dodging cost the villain" question) comes from bots actually playing the game out and is
   contaminated by both sides' bot quality.

5. **`caught = 0` is a property of rational dodging, not a measurement failure.** This was
   independently confirmed by code review, not left unverified. Nothing in a future pass should try
   to force it non-zero — a non-zero `caught` rate against a villain that always notices its own name
   would itself be the bug. `callCgt` ships as its own column so this stays visible rather than
   implied.

6. **No item was ever spent. Not once, in 24,000 games.** Every bot hardcodes `itemUses: []`, so
   across the entire matrix the Lantern fired 0 times, the Keyhole 0 times and the Bell 0 times.
   Three consequences: `src/rules/itemEffects.ts` is dead code in every swept game; **two of the
   ten constraint rows in spec §6.1 (Keyhole and Bell) contributed nothing to any number in this
   document**; and items in this sweep function purely as Call currency, never as the information
   instruments the design intends them to be. Every statement above about what oddities and items are
   worth is a statement about *half* of each mechanic. Building item-spending bots is the second
   cheapest experiment left in this harness, after Call-aware dusk positioning.

Two smaller reading notes that do not rise to limits:

- **`hidingSpace` is retrospective, not live.** `solve`'s backward pass prunes night *n* using the
  nights that came after it, so `hidingSpace[n]` is how narrow the villain's story looks *once the
  game is over*, not how narrow it looked to anyone during night *n*. A "collapse on night 4" is a
  fact a reader of the full record can establish, not necessarily one the table had on night 4. The
  measured effect is small — most collapses come from a single lit-room witness, which is live
  information — but "a real exposure, not a hypothetical one" overstated the timing.
- **Half of all games run a weaker solver.** A public oddity is the child speaking (R18), so when the
  villain owns one its output is theirs to lie about — as deniable as Wren's or Sparrow's private
  oddities, which the solver already refuses to use for that exact reason. Bell's, Clem's **and
  Pike's** constraints are therefore all skipped when the villain is that child. The villain owns one
  of the three in **49.8%** of games (995 of 2,000 at baseline: Bell 349, Pike 320, Clem 326), and
  those games are averaged into every collapse and hiding figure above without a separate column.
  (Pike's guard was added in this pass — it had been missing while Bell's and Clem's were present.
  It moves `hiding` by about +0.02 across the matrix and `lateColl` not at all.)

## What comes after this document

Not this task's call to make, but worth stating plainly since specific outcomes were flagged in
advance as the load-bearing branch points:

- **The Hush question (spec §3.1) now has an answer, and it favours the fallback.** `oneNight` buys
  back 12.8 points of consequential late exposure (18.2% → 31.0%) and 1.5 rooms of the villain's
  average cover (6.084 → 4.573, essentially all of what turning the Hush off achieves). `none` gets
  to 52.1% but throws the mechanic away entirely. This is the largest rule-level effect in the matrix
  and it is the one §3.1 said could change the design. It should be decided before a human plays —
  bearing in mind that it moves no win rate against these bots (see the Hush section).
- **Re-run `lateColl` against a stronger villain, not `collapse`.** Night 1 already floors `collapse`
  near its ceiling regardless of config. This sweep's villain wanders into shared midnight rooms with
  no theft-approach planning; a villain with real approach discipline might reduce late exposure
  further, and 18.2% is low enough that it matters whether the true figure is 18% or 8%.
- **Give the children's bot Call-aware dusk positioning, and change no rules until it has run.**
  Q3 came back "yes, and nothing in the rules is stopping it." The item pool is ~3 eligible players a
  night against a requirement of 2, and ~2.4 of them can legally reach the named bedroom over the
  full night they get to walk it — both above the bar. About 70% of fizzles had a legal path nobody
  took, because `heuristicBot.dusk` spends dusk chasing items and never walks toward a posted Call.
  §12 Q2's flagged emergency fix ("cheaper join cost or more items") is aimed at a constraint that
  is not binding, and `items-on-map-4` confirms more items buy almost nothing — but **no map or
  walk-length change is indicated either**, and this document previously said one was. Fix the bot,
  re-measure, and only then ask whether the Call needs help.
- **Marking is the cleanest complexity-cut candidate**, and now has the decisive number: 0.392
  firings per game, moving nothing but a 4% relative dip in a Call rate that geometry already
  dominates.
- **The dodge-cost question (Q4) is unresolved, not answered "no."** The villain is failing its
  5-theft quota by a wide margin (3.37/5) for reasons that look structural to the bot, and that
  failure swamps whatever the Call is or isn't costing it.
- **Spend some items.** Limit 6 is the one gap that a single afternoon of bot work closes, and it
  would put real numbers under two spec §6.1 constraint rows that have never contributed anything.

The hotseat build (spec §10) is the next honest step regardless — it's the cheapest way to find out
whether any of the above holds up against six people who cluster, follow, and camp, which this
harness was never able to simulate (Limit 1).

### Booked follow-ups: three leaks that are inert now and go live with item-spending bots

None of these affects a single number above. All three are dormant for the same reason — Limit 6, no
item has ever been spent — and the document's own next recommendation is to build the bots that spend
them. Recorded here so they are fixed before that happens, not after.

1. **The villain's report reads `lit` one step too late.** `runMorning` calls
   `clearNightlyItemEffects` before building reports, so `isLit` no longer sees last night's
   Lanterns. An innocent's report carries `lit` from their midnight sighting, taken while the Lantern
   was burning; the villain's is recomputed after it went out. A villain claiming a lantern-lit
   bedroom would therefore report `lit: false` where every truthful occupant of that room reports
   `lit: true` — a one-bit tell that identifies them, and precisely the class of leak R19 exists to
   close.
2. **`reportOf` can still return `null` for a villain who is allowed to speak.** It does so when the
   claim is `null`, which no current bot produces. If one ever did, the villain would go silent on a
   morning the Hush permitted — reinstating exactly the tell R19 was written to prevent (on night one
   nobody is Hushed, so the only silent child is the villain). A `claim ?? position` fallback would
   make the guarantee structural rather than dependent on bot behaviour.
3. **Sparrow's oddity is broadcast to everybody.** `resolveOddities` pushes `thiefFloor` into the
   public event stream, where all six players can read it, while spec §8 gives that information to
   Sparrow alone. It is excluded from `PUBLIC_ODDITIES`, so the solver never uses it and no bot reads
   it today — but it is either private, in which case it does not belong in the public log, or
   public, in which case the solver is leaving real evidence unused. It needs a ruling either way.
